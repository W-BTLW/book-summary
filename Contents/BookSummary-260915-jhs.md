# Chapter 11. 자주 쓰는 서버 구조와 설계 패턴

### 1) MVC 패턴 (Model-View-Controller)
* **개념 및 구조:** 요청 처리(Controller), 비즈니스 데이터 및 로직(Model), 사용자 인터페이스(View)로 역할을 분리하는 웹 표준 아키텍처 패턴이다.
* **포인트:** 
  * 백엔드 API 서버 환경에서는 View 대신 JSON/XML 형태의 데이터 반환(API Controller) 구조를 주로 취함.
  * Controller는 요청 검증 및 응답 형환 역할에 집중해야 하며, 비즈니스 로직이 Controller에 집중되지 않도록 제어하는 것이 핵심임.

### 2) 계층형 아키텍처
* **개념 및 구조:** 애플리케이션을 표현-응용-도메인-인프라
*  등 상하 계층으로 구분하여 각 계층의 관심사를 분리하는 구조이다.
* **포인트:**
  * 하위 계층은 상위 계층을 알지 못하며, 상위 계층이 하위 계층에 의존하는 단방향 의존성을 유지해야 함.
  * 도메인 영역이 거의 없는 계층 구조일 경우 도메인 로직이 분산되는 경향이 있어 유지보수가 어려울 수 있음.

### 3) DDD와 전술 패턴
* **개념 및 구조:** 비즈니스 도메인 중심의 코드 구성을 위해 엔티티(Entity), 밸류 객체(Value Object), 애그리게잇(Aggregate), 리포지토리(Repository) 등 전술적 패턴을 활용하는 설계 방식이다.
* **포인트:**
  * DB 데이터 중심 설계(Anemic Domain Model)에서 벗어나 도메인 객체 자체에 핵심 비즈니스 로직을 모아 응집도를 제고함.
  * 복잡도가 높은 비즈니스 규칙의 상태 변경 기준을 명확히 하고 유지보수성을 극대화함.

### 4) 마이크로서비스 아키텍처 (MSA)
* **개념 및 구조:** 단일 거대 시스템을 독립적으로 배포 및 확장 가능한 소규모 서비스 단위로 분할하여 구성하는 아키텍처이다.
* **포인트:**
  * 서비스 간 결합도 감소 및 독립적 배포와 지속적인 배포가 용이함.
  * 서비스 분리에 따라 발생하는 분산 트랜잭션 관리,  데이터 일관성 유지 문제 등 시스템 복잡도 증가에 대한 대책이 수반되어야 함.

### 5) 이벤트 기반 아키텍쳐
* **개념 및 구조:** 시스템 내부 또는 서비스 간 상태 변화를 '이벤트' 형태로 생성하고, 이를 감지하는 모듈이 비동기적으로 처리하는 구조이다.
* **포인트:**
  * 생산자와 소비자가 직접 연결되지 않고 브로커를 통해 간접적으로 연결되어 있기에, 독립적 배포 및 새로운 소비자 추가 용이

### 6) CQRS 패턴 (Command Query Responsibility Segregation)
* **개념 및 구조:** 데이터의 변경을 담당하는 모델과 조회를 담당하는 모델을 분리하는 패턴이다.
* **포인트:**
  * 조회 성능 최적화를 위하여 명령 모델과 조회 모델을 서로 다른 기술로 구현 가능
