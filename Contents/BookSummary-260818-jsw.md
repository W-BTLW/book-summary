Chapter 10. 네트워크 기초

1. 네트워크 기본 개념

노드(Node)

네트워크에서 데이터를 송수신하는 모든 장치를 의미한다.

예:

* PC
* 스마트폰
* 서버
* 라우터
* 네트워크 장비

네트워크(Network)

여러 노드가 서로 데이터를 주고받을 수 있도록 연결된 시스템이다.

패킷(Packet)

네트워크를 통해 전송되는 데이터의 단위이다.

일반적으로 다음과 같이 구성된다.

* Header: 출발지, 목적지, 프로토콜, 제어 정보 등
* Payload: 실제 전달하려는 데이터

데이터가 큰 경우 여러 개의 패킷으로 나누어 전송할 수 있다.

라우터(Router)

서로 다른 네트워크 사이에서 패킷을 전달하는 장비이다.

⸻

2. IP 주소와 도메인

IP 주소

네트워크에서 노드를 식별하기 위한 주소이다.

IPv4

IPv4 주소는 32비트이며, 일반적으로 4개의 숫자 블록으로 표현한다.

예:

192.168.0.10

IP는 크게 공인 IP와 사설 IP로 구분할 수 있다.

고정 IP와 동적 IP

* 고정 IP: 변경되지 않도록 고정해서 사용하는 IP
* 동적 IP: DHCP 서버 등을 통해 자동으로 할당받는 IP

⸻

도메인(Domain)

사람이 기억하기 쉬운 이름으로 IP 주소를 대신하는 주소이다.

example.com

IP 주소와 도메인의 연결 관계를 관리하는 시스템이 DNS이다.

⸻

DNS(Domain Name System)

도메인 이름을 IP 주소로 변환하는 시스템이다.

example.com
      ↓
     DNS
      ↓
1.2.3.4

DNS는 인터넷의 전화번호부와 같은 역할을 한다.

hosts 파일

DNS 서버를 이용하지 않고 로컬에서 도메인과 IP를 직접 매핑할 수도 있다.

192.168.0.10 example.com

일반적인 이름 해석 과정에서는 로컬의 hosts 설정이 DNS보다 우선적으로 사용될 수 있다.

⸻

3. 공인 IP와 사설 IP

공인 IP(Public IP)

인터넷에서 사용하는 외부용 IP 주소이다.

인터넷상에서 네트워크를 식별하기 위해 사용되며, ISP(통신사) 등을 통해 할당받는다.

사설 IP(Private IP)

내부 네트워크에서 사용하는 IP 주소이다.

대표적인 사설 IP 대역은 다음과 같다.

10.0.0.0 ~ 10.255.255.255
172.16.0.0 ~ 172.31.255.255
192.168.0.0 ~ 192.168.255.255

사설 IP는 인터넷 전체에서 유일할 필요가 없다.

따라서 서로 다른 네트워크에서는 동일한 사설 IP를 사용할 수 있다.

⸻

4. NAT(Network Address Translation)

NAT는 네트워크 주소를 다른 주소로 변환하는 기술이다.

대표적으로 사설 IP와 공인 IP 사이의 변환에 사용된다.

일반적으로 라우터, 방화벽, NAT 장비 등에서 처리한다.

SNAT(Source NAT)

출발지 주소를 변환한다.

주로 내부 → 외부 통신에서 사용한다.

사설 IP
   ↓
  SNAT
   ↓
공인 IP

DNAT(Destination NAT)

목적지 주소를 변환한다.

주로 외부 → 내부 통신에서 사용한다.

공인 IP
   ↓
  DNAT
   ↓
사설 IP

PAT/NAPT

실제 인터넷 환경에서는 하나의 공인 IP를 여러 내부 장치가 공유하는 경우가 많다.

이때 IP 주소뿐만 아니라 Port 번호까지 함께 변환하여 여러 연결을 구분한다.

192.168.0.10:50001 ─┐
192.168.0.11:50002 ─┼→ 공인 IP:Port
192.168.0.12:50003 ─┘

이를 통해 하나의 공인 IP를 여러 장치가 공유할 수 있다.

NAT가 IPv4 유지에 기여한 이유

IPv4 주소는 약 43억 개로 제한되어 있다.

NAT/PAT를 이용하면 여러 장치가 하나의 공인 IP를 공유할 수 있기 때문에 IPv4 주소 고갈을 상당 부분 지연시킬 수 있었다.

⸻

5. VPN(Virtual Private Network)

VPN은 공용 네트워크인 인터넷을 통해 가상의 사설 네트워크를 구성하는 기술이다.

서로 떨어져 있는 네트워크 사이에 암호화된 터널을 구성하여 마치 하나의 사설 네트워크처럼 통신할 수 있다.

[내부 네트워크 A]
        │
   암호화된 VPN 터널
        │
[내부 네트워크 B]

주요 목적은 다음과 같다.

* 통신 데이터 암호화
* 외부에서 내부 네트워크에 안전하게 접근
* 서로 다른 네트워크 간 연결

⸻

6. 프로토콜과 네트워크 계층

프로토콜(Protocol)

네트워크에서 두 노드가 데이터를 주고받기 위해 정의한 통신 규칙이다.

대표적인 프로토콜을 계층별로 구분하면 다음과 같다.

계층	대표 프로토콜
애플리케이션 계층	HTTP, FTP, SMTP
전송 계층	TCP, UDP
네트워크 계층	IP
데이터 링크 계층	Ethernet
물리 계층	케이블, 전기 신호 등

여기서 **TCP, UDP는 전송 계층(L4)**에 해당하며, IP는 네트워크 계층(L3)에 해당한다.

⸻

7. TCP

**TCP(Transmission Control Protocol)**는 연결 지향적이며 신뢰성 있는 데이터 전송을 제공하는 전송 계층 프로토콜이다.

3-Way Handshake

TCP는 데이터를 전송하기 전에 연결을 수립한다.

Client                Server
  │ ----- SYN ------> │
  │ <--- SYN + ACK -- │
  │ ----- ACK ------> │
       연결 수립

TCP의 주요 특징

* 연결 지향
* 3-Way Handshake
* 데이터 순서 보장
* 패킷 유실 감지
* 패킷 재전송
* ACK를 통한 수신 확인
* Sequence Number를 통한 데이터 순서 관리

따라서 신뢰성 있는 데이터 전송이 필요한 경우 적합하다.

TCP의 HOL(Head Of Line) Blocking

TCP에서는 하나의 연결에서 데이터의 순서를 보장해야 한다.

예를 들어 특정 패킷이 유실되면 이후 패킷이 먼저 도착하더라도 순서상 해당 패킷을 기다려야 할 수 있다.

패킷 1 → 정상
패킷 2 → 유실
패킷 3 → 도착
패킷 4 → 도착
          ↓
     패킷 2 대기
          ↓
   패킷 2 재전송
          ↓
      이후 처리

이러한 특성 때문에 패킷 손실이 전체 데이터 처리에 영향을 줄 수 있다.

⸻

8. UDP

**UDP(User Datagram Protocol)**는 연결을 수립하지 않고 데이터를 바로 전송하는 전송 계층 프로토콜이다.

TCP와 달리 다음과 같은 기능을 기본적으로 제공하지 않는다.

* 연결 수립
* 데이터 순서 보장
* 수신 확인
* 패킷 재전송

따라서 구조가 단순하고 전송 과정의 오버헤드가 적다.

Client                Server
  │ ----- Data ------> │
  │ ----- Data ------> │
  │ ----- Data ------> │

UDP 특징

* 비연결형
* 별도의 Handshake 없음
* 순서 보장 없음
* 재전송 없음
* 신뢰성 보장 없음
* 상대적으로 낮은 오버헤드

⸻

9. TCP vs UDP

구분	TCP	UDP
연결 방식	연결 지향	비연결
연결 과정	3-Way Handshake	없음
순서 보장	O	X
패킷 재전송	O	X
수신 확인	O	X
신뢰성	높음	낮음
오버헤드	상대적으로 높음	낮음
HOL Blocking	발생 가능	해당 없음

단순히 TCP는 느리고 UDP는 빠르다라고 이해하기보다는,

TCP는 신뢰성과 순서 보장을 위해 추가적인 기능을 제공하고, UDP는 이러한 기능을 최소화하여 단순한 데이터그램 전송을 제공한다.

라고 이해하는 것이 정확하다.

⸻

10. QUIC

**QUIC(Quick UDP Internet Connections)**는 UDP 위에 구현된 현대적인 전송 프로토콜이다.

UDP 자체는 신뢰성이나 순서 보장을 제공하지 않지만, QUIC가 이러한 기능을 자체적으로 구현한다.

구조는 다음과 같다.

Application
     │
    QUIC
     │
    UDP
     │
     IP

기존의 일반적인 TCP 기반 구조는 다음과 같다.

Application
     │
    TCP
     │
     IP

QUIC의 주요 특징

* UDP 기반
* 연결 관리
* 패킷 손실 감지 및 재전송
* 데이터 순서 관리
* 암호화 통신
* 다중 Stream 지원
* 빠른 연결 수립

⸻

11. QUIC과 HOL Blocking

TCP는 하나의 연결에서 데이터 순서를 관리하기 때문에 패킷 손실이 전체 데이터 처리에 영향을 줄 수 있다.

반면 QUIC은 하나의 연결 안에서 데이터를 여러 개의 독립적인 Stream으로 나눌 수 있다.

QUIC Connection
├─ Stream 1 → 패킷 유실 / 재전송
├─ Stream 2 → 정상 처리
└─ Stream 3 → 정상 처리

따라서 Stream 1에서 패킷 손실이 발생하더라도 Stream 2와 Stream 3은 계속 처리할 수 있다.

즉, QUIC은 TCP의 전송 계층 전체에 걸친 HOL Blocking 문제를 Stream 단위로 줄일 수 있다.

⸻

12. QUIC의 암호화와 연결 수립

QUIC은 TLS를 통합하여 기본적으로 암호화된 통신을 제공한다.

또한 TCP + TLS 방식에서 발생하는 연결 수립 과정을 줄여 빠른 연결 수립을 목표로 한다.

일반적으로 QUIC은 1-RTT 연결 수립을 사용하며, 조건이 충족되는 경우 0-RTT도 지원한다.

⸻

13. TCP vs UDP vs QUIC

구분	TCP	UDP	QUIC
기반	TCP	UDP	UDP
연결 관리	TCP에서 제공	없음	QUIC에서 제공
순서 관리	O	X	O
재전송	O	X	O
신뢰성	O	X	O
암호화	별도로 TLS 사용 가능	자체 제공하지 않음	TLS 기반 암호화 통합
다중 Stream	X	X	O
HOL Blocking	연결 수준에서 발생 가능	해당 없음	Stream 단위로 영향 감소
연결 수립	TCP Handshake + 필요 시 TLS	없음	1-RTT / 조건에 따라 0-RTT
특징	신뢰성 중심	단순성·낮은 오버헤드	빠른 연결 + 신뢰성 + 다중 Stream

⸻

14. 전체 개념 요약

네트워크를 큰 흐름으로 보면 다음과 같이 이해할 수 있다.

사용자
  ↓
Application
  ↓
HTTP 등 애플리케이션 프로토콜
  ↓
TCP / UDP / QUIC
  ↓
IP
  ↓
Ethernet 등
  ↓
Network

그리고 주소와 네트워크 연결 관점에서는 다음과 같다.

도메인
  ↓
 DNS
  ↓
IP 주소
  ↓
라우터
  ↓
NAT
  ↓
인터넷

핵심 개념만 압축하면 다음과 같다.

* 패킷 → 네트워크를 통해 전달되는 데이터 단위
* IP → 네트워크에서 노드를 식별하는 주소
* 도메인 → IP를 사람이 기억하기 쉽게 표현한 이름
* DNS → 도메인과 IP를 연결하는 시스템
* 공인 IP → 인터넷에서 사용하는 외부 주소
* 사설 IP → 내부 네트워크에서 사용하는 주소
* NAT → IP/Port 주소를 변환하는 기술
* VPN → 공용 네트워크 위에 암호화된 가상 사설망을 구성하는 기술
* 프로토콜 → 네트워크 통신을 위한 규칙
* TCP → 연결 + 신뢰성 + 순서 보장
* UDP → 단순한 비연결형 데이터 전송
* QUIC → UDP 기반 + 신뢰성 + 연결 관리 + 다중 Stream + 암호화

한 줄로 정리

TCP는 신뢰성을 제공하는 연결형 전송 프로토콜이고, UDP는 단순하고 낮은 오버헤드의 전송 프로토콜이며, QUIC은 UDP 위에 TCP의 신뢰성과 연결 관리 기능 등을 구현하면서 다중 Stream과 빠른 연결 수립을 제공하는 프로토콜이다.
