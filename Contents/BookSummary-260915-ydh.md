# 자주쓰는서버구조와설계패턴

## MVC패턴
### Model-View-Controller
### Model : 비즈니스 영역 로직
### View : 사용자에게 보여줄 결과 생성하여 응답
### Controller : 입출력 흐름 제어

## 계층형 아키텍처
### 각 계층마다 특정 역할을 수행하고, 하위에 위치한 계층에만 의존하는 특징
### 구조가 단순하고 규칙이 명확하여 코드 실행흐름 추적 쉽다

## DDD
### 도메인 영역에 도메인 로직을 집중
### 도메인 로직을 묶고 복작한 모델을 도메인단위로 관리하여 복잡도 낮추고 관련 로직을 모아 응집도를 높여 도메인의 유지보수성 높여줌

## 마이크로 서비스
### 더 작은 서비스를 분리하고 각 서비스가 연동되는 구조
### 독립적 배포 최우선 고려
### 만능은 아니고 모놀리식이랑 잘 고려해보자

## 이벤트 기반 아키텍처
### 이벤트 생산자/소비자/브로커(라우터)로 구성
### 생산자는 브로커에 전달하고 브로커는 관심있는 소비자에게 전달하고 소비자는 이벤트를 받아 적절하게 반응

## CQRS
### 단일 모델 사용으로 인해 발생하는 복잡도 문제 해결가능
### 명령모델과 조회모델 구분함으로써 상호 영향 최소화
### 조회모델이 따로여서 조회 성능 향상시키기 쉬움, 다만 기능마다 모델 따로 만들어야해서 작업량은 상승
