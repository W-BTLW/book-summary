## 네트워크 IO와 자원 효율
##### 스레드 블로킹(blocking)
코드 실행 -> write() 시작 -> `스레드 대기(데이터 전송)` -> write() 리턴 -> read() 시작 -> `스레드 대기(데이터 수신)` -> read()리턴
※블로킹 : 작업이 완료될 때까지 스레드가 대기하는 것. 주로 입출력과정에서 발생

스레드가 대기한다? == CPU 낭비
메모리를 늘리면 되지 않나? -> 컨텍스트 스위칭에 사용되는 시간이 증가

##### CPU 효율
트래픽이 증가하면 다음과 같은 이유로 자원 효율이 떨어진다
1. IO 대기와 컨텍스트 스위칭에 따른 CPU 낭비
2. 요청마다 스레드를 할당함으로써 메모리 사용량이 높음

해결방법
1. 서버 수평/수직 확장
2. IO대기로 인한 CPU 낭비를 줄이고 요청을 처리하는 데 필요한 메모리를 줄이는 것
   1) 가상 스레드나 고루틴 같은 경량 스레드 사용
   2) 논블로킹 또는 비동기 IO 사용

## 가상 스레드
가상 스레드와 고루틴은 경량 스레드다.
경량스레드는 OS가 관리하는 스레드가 아니라 JVM같은 언어의 런타임이 관리하는 스레드다.
경량스레드(가상스레드)는 플랫폼 스레드(OS스레드)보다 더 적은 메모리를 사용한다.

</br>

가상스레드는 실행하는 과정에서 블로킹되면 플랫폼 스레드와 언마운트되고 실행이 멈춘다.
이때 언마운트된 플랫폼 스레드는 실행 대기 중인 다른 가상 스레드와 연결된 뒤 실행을 재개한다.

</br>

참고)
플랫폼스레드 생성 : Thread thread = Thread.ofPlatform().start(() -> {})
가상스레드 생성 : Trhead thread = Thread.ofVirtual

</br>

##### 블로킹 연산과 synchronized
블로킹 연산에는 `IO기능`, `ReentrantLock`, `Thread.sleep()`등이 포함된다.
자바23또는 이전 버전에서 synchronized로 인해 블로킹되면, 가상 스레드는 플랫폼 스레드로부터 언마운트되지 않는다.
즉, 플랫폼 스레드도 같이 블로킹된다.

</br>

##### 가상 스레드와 성능
- IO중심 작업 (여기서 더 효과 있음 !!)
  - 가상스레드가 플랫폼 스레드보다 개수가 많을 때 효과가 있다
- CPU중심 작업

가상 스레드를 사용해서 높일 수 있는 것은 처리량이다.
가상 스레드를 사용한다고 해서 실행속도가 플랫폼 스레드보다 더 빨라지지는 않는다.

</br>

##### 가상 스레드 장점
1. 기존 코드를 크게 수정할 필요가 없다
2. 플랫폼스레드보다 생성 비용이 적기 때문에 스레드풀을 미리 구성할 필요가 없다.


</br>

## 논블로킹 IO
경량스레드도 한계가 왔을 때 논블로킹 IO를 사용해야한다.
논블로킹 IO는 입출력이 끝날 때까지 스레드가 대기하지 않는다.
논블로킹 IO에서 동시성을 높이기 위해서 사용하는 방법은 채널들을 N개의 그룹(=CPU 개수)으로 나누고, 각 그룹마다 스레드를 생성하는 것이다.

</br>

##### 리액터 패턴
`리액터`는 이벤트가 발생할 때까지 대기하다가 이벤트가 발생하면 알맞은 `핸들러`에 이벤트를 전달한다.
이벤트를 받은 핸들러가 필요한 로직을 수행한다
