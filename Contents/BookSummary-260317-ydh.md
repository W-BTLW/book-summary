# 🚀 비동기 연동 방식 및 효율화 전략

> **핵심 원칙:** 비즈니스 로직의 성격에 따라 **연동(Sync) / 비동기(Async)** 방식을 유연하게 선택하여 시스템 효율을 극대화한다.

---

## 1. 별도 스레드(Thread)로 실행하기
가장 단순하고 직관적인 비동기 처리 방식입니다.

* **특징:** 구현이 매우 쉬움.
* **주의사항:** * 비동기 실행 중 발생하는 **오류 처리(Exception Handling)** 로직을 철저히 설계해야 함.
    * 효율적인 메모리 관리를 위해 **OS 스레드**와 **가상 스레드(Virtual Thread)**의 특성을 비교하여 적절한 모델을 선택해야 함.

## 2. 메시징 (Messaging)
시스템 사이에 메시지 브로커를 두어 결합도를 낮추는 방식입니다.

* **특징:** 생산자(Producer)와 소비자(Consumer)가 서로의 변경에 영향을 받지 않음 (디커플링).
* **대표 기술:**
    * **Kafka:** 대용량 트래픽 처리에 최적화.
    * **RabbitMQ:** 트래픽이 아주 크지 않고, 메시지의 정확한 전달(Routing)이 중요할 때.
    * **Redis Pub/Sub:** 단순한 구현, 메시지 유실이 발생해도 무방한 가벼운 서비스에 적합.
* **전략:**
    * 메시지 유실 시 대응: **무시 / 재시도 / 실패 로그 기록** 중 상황에 맞게 선택.
    * **글로벌 트랜잭션:** 여러 자원에 대한 변경을 하나의 트랜잭션 단위로 묶어 정합성 유지 가능.
* **메시지 종류:**
    1.  **이벤트(Event):** "어떤 일이 발생했음"을 알리는 메시지.
    2.  **커맨드(Command):** "무언가를 처리하라"고 요청하는 메시지.

## 3. 트랜잭션 아웃박스 패턴 (Transaction Outbox Pattern)
메시지 발행의 원자성을 보장하기 위한 패턴입니다.

* **방식:** 메시지 데이터를 비즈니스 로직과 동일한 **DB 내 Outbox 테이블에 안전하게 저장**한 후, 별도 프로세스가 이를 읽어 메시징 시스템으로 전송함.
* **장점:** DB 업데이트와 메시지 발행이 동일한 트랜잭션 내에서 처리되어 데이터 일관성이 보장됨.

## 4. 배치 연동 (Batch Interface)
실시간성이 중요하지 않은 데이터를 대량으로 처리하는 전통적인 방식입니다.

* **특징:** 일정 간격(스케줄)마다 한꺼번에 데이터를 전송.
* **전송 방식:**
    * **파일 전송:** FTP/SFTP 프로토콜 또는 SCP 명령어 활용.
    * **DB 디퍼드(Deferred):** DB to DB 연동 방식.
* **주의사항:** 장애 발생 시 해당 지점부터 다시 시작할 수 있는 **재처리(Retry/Restart) 기능** 필수.

## 5. CDC (Change Data Capture)
데이터베이스의 변경 사항을 실시간으로 추적하여 연동하는 소프트웨어 패턴입니다.

* **방식:** DBMS가 제공하는 트랜잭션 로그 등을 활용하여 변경 내용(Insert, Update, Delete)을 감지하고 통지함.
* **장점:** 소스 시스템의 비즈니스 로직 수정 없이 DB 레벨에서 변경 데이터를 추출하여 타 시스템으로 전동 가능.
