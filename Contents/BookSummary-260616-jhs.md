# Chapter 08. 실무에서 꼭 필요한 보안 지식

## 1. 인증과 인가

### 인증(Authentication)

사용자가 누구인지 확인하는 과정이다.

예시
- 아이디/비밀번호 로그인
- 비대면 실명확인
- 휴대폰 본인인증

### 인증과 토큰

인증이 성공하면 서버는 사용자를 식별하기 위한 토큰 또는 세션을 발급한다.

대표적인 방식
- Session 기반 인증
- JWT 기반 인증

토큰 자체가 인증을 의미하는 것은 아니며, 서버는 토큰의 유효성을 검증한 후 사용자를 식별한다.

---

### 인가(Authorization)

인증된 사용자가 어떤 자원에 접근할 수 있는지 결정하는 과정이다.

예시
- 일반 사용자는 자신의 정보만 조회 가능
- 관리자는 전체 사용자 조회 가능

즉,

- 인증 = 누구인가?
- 인가 = 무엇을 할 수 있는가?

---

### 인가와 접근 제어 모델

#### RBAC (Role Based Access Control)

역할(Role)에 따라 권한을 부여하는 방식

예시
- USER
- ADMIN
- MANAGER

실무에서 가장 많이 사용된다.

#### ABAC (Attribute Based Access Control)

사용자 속성, 리소스 속성, 환경 정보 등을 기반으로 권한을 결정하는 방식

예시
- 서울 지점 직원만 조회 가능
- 영업시간에만 접근 가능

세밀한 권한 제어가 가능하지만 구현 복잡도가 높다.

---

## 2. 데이터 암호화

### 단방향 암호화

암호화 후 원본 데이터를 복원할 수 없는 방식이다.

주로 비밀번호 저장에 사용한다.

#### 해시 함수(Hash Function)

입력값을 고정 길이의 해시값으로 변환한다.

특징
- 단방향
- 복원 불가
- 동일 입력은 동일 결과

대표 알고리즘
- SHA-256
- SHA-512

#### 솔트(Salt)로 보안 강화하기

비밀번호에 임의의 값을 추가한 후 해시를 수행한다.

목적
- 레인보우 테이블 공격 방어
- 동일 비밀번호의 동일 해시값 생성 방지

---

### 양방향 암호화

암호화된 데이터를 다시 복호화할 수 있는 방식이다.

주로 개인정보나 금융정보 저장에 사용한다.

#### AES (대칭 키 암호화)

암호화와 복호화에 동일한 키를 사용한다.

장점
- 빠름
- 대용량 데이터 처리에 적합

단점
- 키 관리가 어려움

사용 예
- 개인정보 암호화
- DB 컬럼 암호화

---

#### 비대칭 키 암호화

공개키(Public Key)와 개인키(Private Key)를 사용하는 방식이다.

장점
- 키 전달이 안전함

단점
- 연산 속도가 느림

사용 예
- HTTPS
- 전자서명
- 인증서

---

## 3. HMAC을 이용한 데이터 검증

공유된 비밀키와 해시 함수를 이용하여 데이터 위변조 여부를 검증하는 기술이다.

---

## 4. 방화벽으로 필요한 트래픽만 허용하기

허용된 IP, 포트, 프로토콜만 통과시키고 나머지는 차단하여 공격 표면을 줄인다.

---

## 5. 감사 로그 남기기

사용자 행동과 중요 시스템 변경 이력을 기록하여 추적 가능성을 확보한다.

---

## 6. 비정상 접근 처리

이상 로그인, 반복 실패, 비정상 요청 등을 탐지하고 차단하여 보안 사고를 예방한다.

---

## 7. 시큐어 코딩

입력값 검증, SQL Injection 방어, XSS 방어 등 보안 취약점을 예방하는 안전한 개발 방법론이다.
