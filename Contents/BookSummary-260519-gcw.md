# 📡 네트워크 I/O와 CPU, 그리고 동시성 처리 전략

## 1. 네트워크 I/O와 CPU

### 🔹 블로킹 (BLOCKING)

- 블로킹이란 작업이 완료될 때까지 **스레드가 대기하는 상태**를 의미한다.  
- 주로 **데이터 입출력(I/O)** 과정에서 발생한다.  
- 서버처럼 네트워크 연동이 많은 프로그램은 전체 실행 시간의 **90% 이상을 I/O 대기**에 사용하는 경우도 있다.

➡️ 문제점  
- CPU는 일을 하지 못하고 대기 상태가 됨  
- 자원 낭비 발생  

➡️ 해결 시도  
- 스레드 개수를 늘려 대기 시간을 분산 가능  
- 하지만 **물리적인 스레드 생성에는 한계 존재**

---

### 🔹 컨텍스트 스위칭 (CONTEXT SWITCHING)

- 운영체제는 여러 스레드를 번갈아 가며 CPU에 할당한다.  
- 한 스레드를 짧은 시간 실행 후, 다른 스레드로 전환한다.

➡️ 전환 과정  
1. 현재 실행 중인 스레드 상태 저장  
2. 다음 스레드 상태 로드  

➡️ 이 과정을 **컨텍스트 스위칭**이라고 한다.

➡️ 문제점  
- 전환 비용 발생 (CPU 오버헤드)  
- 스레드가 많아질수록 성능 저하 가능  

---

### 🔹 자원 효율 최적화 목표

- I/O 대기로 인한 CPU 낭비 최소화  
- 요청 처리에 필요한 메모리 사용량 감소  

➡️ 이를 해결하기 위한 대표 방법  
1. 가상 스레드 (VIRTUAL THREAD)  
2. 논블로킹 I/O (NON-BLOCKING I/O)

---

## 2. 가상 스레드 (VIRTUAL THREAD)

### 🔹 개념

- JAVA의 가상 스레드 또는 GO의 고루틴(GOROUTINE)과 같은 **경량 스레드**  
- 언어 런타임(JVM 등)이 직접 스케줄링을 수행  

➡️ 특징  
- OS 스레드가 아닌 **런타임 관리 스레드**  
- 매우 적은 자원 사용  
- **수십만 ~ 백만 개 생성 가능**

---

### 🔹 캐리어 스레드 (CARRIER THREAD)

- 가상 스레드를 실행하는 실제 OS 스레드  

➡️ 동작 구조  
- 하나의 캐리어 스레드가 여러 가상 스레드를 실행  
- 가상 스레드가 연결되면 → **마운트 (MOUNT)**  
- 실행 중이면 → 해당 캐리어 스레드 위에서 수행  

---

### 🔹 네트워크 I/O와 가상 스레드

- 가상 스레드는 I/O에서 블로킹 발생 시 다음과 같이 동작한다:

➡️ 동작 흐름  
1. 캐리어 스레드에서 **언마운트 (UNMOUNT)**  
2. 실행 중지  
3. 캐리어 스레드는 다른 가상 스레드 실행  

➡️ 결과  
- OS 스레드는 **유휴 상태 없이 계속 작업 수행**

---

### 🔹 성능과 장점

- I/O 중심 작업에서 매우 효율적  
- 블로킹 API 그대로 사용 가능 (코드 단순함 유지)

➡️ 핵심 장점  
- CPU 낭비 최소화  
- 높은 동시성 처리  
- 스레드 생성 비용 매우 낮음  

➡️ 중요 조건  
- **가상 스레드 수 > 플랫폼 스레드 수** 여야 효과 극대화

---

### 🔹 스레드 풀과의 차이

- 기존: 스레드 풀을 미리 생성하여 재사용  
- 가상 스레드: 생성 비용이 낮아 **미리 생성할 필요 없음**

---

## 3. 논블로킹 I/O (NON-BLOCKING I/O)

### 🔹 개념

- I/O가 완료될 때까지 **스레드가 대기하지 않는다**

---

### 🔹 SELECTOR

- I/O 이벤트가 발생할 때까지 대기하는 메커니즘  

➡️ 동작  
- 이벤트 발생 시 → 수행 가능한 작업 존재  
- 해당 시점에만 작업 수행  

---

### 🔹 블로킹 I/O vs 논블로킹 I/O

| 구분 | 블로킹 I/O | 논블로킹 I/O |
|------|-----------|-------------|
| 스레드 모델 | 커넥션당 1 스레드 | 소수 스레드 |
| 확장성 | 낮음 | 높음 |
| 메모리 사용 | 많음 | 적음 |
| 구조 | 단순 | 복잡 |

➡️ 특징  
- 클라이언트 수 증가해도 **스레드 수는 일정 유지**  
- 동일 자원으로 더 많은 연결 처리 가능  

---

### 🔹 동시성 향상 방법

- 채널을 N개의 그룹으로 분리  
- 각 그룹마다 스레드 할당  

➡️ 결과  
- 병렬 처리 성능 향상  

---

### 🔹 리액터 패턴 (REACTOR PATTERN)

- 논블로킹 I/O에서 사용하는 대표적인 설계 패턴  

➡️ 동작 흐름  
1. 이벤트 발생 대기  
2. 이벤트 발생 시  
3. 적절한 핸들러에 전달  
4. 핸들러가 로직 수행  

---

### 🔹 이벤트 루프 (EVENT LOOP)

- 단일 스레드 기반으로 이벤트 처리  

➡️ 한계  
- 블로킹 작업 발생 시 전체 지연  

➡️ 보완 방법  
- 핸들러 내부에서  
  → 별도 스레드 풀 사용  

---

## 4. 언제 어떤 방법을 선택할까?

### 🔹 가상 스레드 (VIRTUAL THREAD)가 적합한 경우

- I/O 비중이 높은 서비스  
- 기존 **블로킹 코드 유지가 중요한 경우**  
- 개발 생산성을 유지하면서 성능 개선 필요할 때  

➡️ 예시  
- 웹 서버 (SPRING, REST API)  
- DB 호출 중심 서비스  

---

### 🔹 논블로킹 I/O (NON-BLOCKING I/O)가 적합한 경우

- 초고성능 / 초대규모 트래픽 처리  
- 수십만 ~ 수백만 동시 연결 처리 필요  
- 이벤트 기반 아키텍처 설계 가능할 때  

➡️ 예시  
- NETTY 기반 서버  
- 채팅 서버, 실시간 스트리밍  

---

### 🔹 선택 기준 정리

| 기준 | 가상 스레드 | 논블로킹 I/O |
|------|------------|--------------|
| 개발 난이도 | 낮음 | 높음 |
| 코드 복잡도 | 낮음 | 높음 |
| 성능 | 높음 | 매우 높음 |
| 유지보수 | 쉬움 | 어려움 |

---

### 🔹 결론

- **일반적인 서버 개발 → 가상 스레드**  
- **극한 성능 / 대규모 트래픽 → 논블로킹 I/O**  

👉 대부분의 경우  
➡️ 가상 스레드가 **현실적인 최적 선택**
