# 동시성 정리

## ⚠️ 동시성: 데이터가 꼬이기 전에 잡아야 한다

---

## 1. 서버의 동시 요청 처리 방식

서버가 동시에 여러 클라이언트 요청을 처리하는 방식은 크게 두 가지다.

* **스레드 기반 처리**

  * 클라이언트 요청마다 별도의 스레드를 할당하여 처리

* **비동기 I/O 기반 처리**

  * 논블로킹 방식으로 요청을 처리하여 효율적으로 자원 활용

> 초보 개발자들이 가장 실수하기 쉬운 영역 중 하나

---

## 2. 프로세스 수준에서의 동시 접근 제어

### 🔒 잠금(Lock)을 이용한 방식

```
잠금 획득 → 공유 자원 접근 (임계 영역) → 잠금 해제
```

* 여러 스레드가 동시에 접근하지 못하도록 제어

---

## 3. 데이터베이스와 동시성

### 🔐 비관적 락 (Pessimistic Lock)

* 먼저 접근한 트랜잭션이 잠금을 획득
* 다른 트랜잭션의 접근을 차단

### 🔓 낙관적 락 (Optimistic Lock)

* 명시적으로 잠금을 사용하지 않음
* 데이터 수정 시점에 값 비교로 충돌 감지

  * 조회 시점 값 vs 수정 시점 값

---

## 4. 잠금 사용 시 주의사항

* 잠금 해제를 반드시 수행해야 한다
* 적절한 대기 시간(Timeout)을 설정해야 한다
* 교착 상태(Deadlock)를 피해야 한다

---

## 5. 단일 스레드 처리 고려

* 동시성 문제가 발생하는 근본 원인:

  > 여러 스레드가 동일 자원에 동시에 접근하기 때문

* 상황에 따라 단일 스레드 처리도 고려 가능

---

## 6. 동시성 관련 용어

* **경쟁 상태 (Race Condition)**
* **임계 영역 (Critical Section)**
* **뮤텍스 (Mutex)**
* **세마포어 (Semaphore)**
* **불변 값 (Immutable)**
* **분산 잠금 (Distributed Lock)**
* **증분 쿼리 (Incremental Query)**
* **라이브 락 (Live Lock)**
* **기아 상태 (Starvation)**
