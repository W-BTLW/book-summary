# 📘 6장. 동시성, 데이터가 꼬이기 전에 잡아야 한다 (구조별 핵심 정리)

## 1. 프로세스 수준에서의 동시 접근 제어

- 하나의 애플리케이션 내부에서 동시성 제어
- 대표 방법:
  - synchronized
  - Lock (ReentrantLock 등)
  - Concurrent 자료구조

### ✔️ 특징
- 같은 프로세스(= JVM) 안에서만 유효
- 구현이 비교적 단순
- 분산 환경에서는 동시성 제어 불가

---

## 2. DB와 동시성

- 실무에서 가장 중요한 동시성 제어 지점
- 데이터 정합성은 결국 DB가 책임짐

### ✔️ 핵심 방법

#### 1) 트랜잭션
- 작업을 하나의 단위로 묶음
- 중간 상태 노출 방지

#### 2) 락 (Lock)
- 비관적 락: 미리 잠그고 작업
- 낙관적 락: 충돌 시 재시도

#### 3) 쿼리로 해결
```sql
UPDATE account 
SET balance = balance - 1000 
WHERE id = 1;
```

👉 조회 + 수정 분리하지 않고 **한 번에 처리**

---

### ✔️ 핵심 포인트
- "조회 → 계산 → 저장" 구조는 위험
- DB가 atomic하게 처리하도록 설계해야 함 -> 쿼리로 계산하

---

## 3. 잠금 사용 시 주의 사항

### ❗ 1) 성능 저하
- 락이 많아질수록 대기 시간 증가

### ❗ 2) 데드락 (Deadlock)
- 서로 락을 기다리며 무한 대기

👉 예방:
- 락 획득 순서 통일
- 트랜잭션 짧게 유지

---

### ❗ 3) 락 범위 문제
- 너무 넓으면 → 성능 저하
- 너무 좁으면 → 동시성 문제 발생

---

### ❗ 4) 과도한 락 사용
- 불필요한 락은 시스템 전체 성능 저하시킴

👉 결론:
- **필요한 최소 범위로, 짧게 사용**

---

## 4. 단일 스레드로 처리하기

- 아예 동시성을 없애는 전략

### ✔️ 방법
- 큐(Queue)에 작업을 넣고 순차 처리
- 메시지 기반 처리 (Kafka, MQ 등)

---

### ✔️ 장점
- 동시성 문제 원천 차단
- 구현이 단순

### ❗ 단점
- 처리 속도 제한 (병목 발생)
- 실시간 처리에 부적합할 수 있음
