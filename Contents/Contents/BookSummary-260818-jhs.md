# 챕터 10. 모르면 답답해지는 네트워크 기초

---

## 1. 공인 IP와 사설 IP
* **공인 IP (Public IP):** ISP(통신사)로부터 할당받아 전 세계 인터넷망에서 유일하게 식별되는 외부용 주소
* **사설 IP (Private IP):** 공유기 등 내부 네트워크(LAN) 안에서 기기 구분을 위해 할당하는 내부용 주소 (`192.168.x.x`, `10.x.x.x` 등)
* **핵심 차이:** 사설 IP는 내부 망에서만 유효하며, 인터넷 외부망으로 직접 통신할 수 없음

---

## 2. NAT (Network Address Translation)
* **개념:** 사설 IP와 공인 IP 사이에서 패킷의 IP 및 Port 주소를 실시간으로 변환해 주는 기술
* **핵심 방식 (PAT/NAPT):** 공인 IP 1개에 수많은 포트 번호를 매핑하여, 라우터/공유기 아래 연결된 여러 기기가 하나의 공인 IP를 공유하게 만듦

---

## 3. 공인/사설 IP와 NAT로 IPv4가 아직 유지되는 이유
* **1:N 주소 공유:** 원래대로라면 기기마다 공인 IP가 필요하지만, NAT를 통해 집·기업당 단 1개의 공인 IP만 사용함
* **주소 고갈 지연:** 약 43억 개의 IPv4 주소 한계를 극복하고 수십~수백억 대의 기기를 접속시킬 수 있게 되어, IPv6로의 전면 전환 없이도 기존 망을 유지 가능함

---

## 4. VPN (Virtual Private Network)
* **개념:** 암호화 터널링 기술을 통해 공용 인터넷망 위에서 마치 전용 가상 사설망을 사용하는 것처럼 통신하는 기술
* **주요 역할:**
  * **보안성 확보:** 데이터를 암호화하여 중간 해킹 및 데이터 감청 방지
  * **접근 제어:** 외부에서 회사 내부 망(사설 IP 대역)으로 안전하게 접근할 때 활용

---

## 5. 3-Way Handshake와 OkHttp 재시도 정리
* **3-Way Handshake:** TCP 연결을 맺는 과정 (`SYN` $\rightarrow$ `SYN-ACK` $\rightarrow$ `ACK`)
* **OkHttp 재시도 및 중복 트랜잭션 오류 원인:**
  * **SYN 단계 실패 시:** 연결 자체가 수립되지 않아 HTTP 요청이 전달되지 않음 (중복 오류 원인 X)
  * **연결 완료(`ACK`) 후 실패 시:** HTTP POST 요청이 서버에 전달되어 비즈니스 로직이 수행 중인데, 응답 대기 과정에서 타임아웃/소켓 단절 발생
  * **문제 발생:** OkHttp의 `retryOnConnectionFailure`가 이를 "네트워크 실패"로 판단해 동일 요청을 재전송함 $\rightarrow$ **서버 측 중복 트랜잭션 장애 발생**

---

## 6. TCP vs UDP vs QUIC 비교

| 구분 | TCP | UDP | QUIC |
| :--- | :--- | :--- | :--- |
| **기반 전송 계층** | L4 (TCP) | L4 (UDP) | L7 (UDP 위에 구현된 프로토콜) |
| **신뢰성 / 순서 보장** | O (손실 시 재전송, 순서 보장) | X (단순 패킷 전송) | O (손실 제어 및 신뢰성 보장) |
| **연결 수립 (Handshake)** | Slow (TCP Handshake + TLS 필요) | 없음 (Connectionless) | Fast (1-RTT 또는 0-RTT) |
| **Head-of-Line Blocking** | 발생 함 (패킷 손실 시 전체 대기) | 없음 | 없음 (스트림 단위 독립 처리) |
| **주요 사용처** | HTTP/1.1, HTTP/2, 웹, 이메일 | DNS, 실시간 스트리밍, 게임 | HTTP/3, 모바일 환경 웹 통신 |
