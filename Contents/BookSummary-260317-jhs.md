# 주니어 백엔드 개발자가 반드시 알아야 할 실무 지식  
## 5장 비동기 연동 요약

---

# 0. 비동기로 처리해도 되는 case

다음 조건이면 **비동기 사용 가능**

- **즉시 결과가 필요 없음**
- **처리가 오래 걸림**
- **실패 시 재처리 가능**
- **서비스 응답 속도에 영향 주면 안 됨**

예

```
이메일 발송
알림 발송
로그 저장
통계 집계
이미지 변환
```

반대로 **동기가 필요한 경우**

```
결제 승인
송금
재고 차감
좌석 예약
```

→ **강한 일관성 필요**

---

# 1. 별도 스레드로 실행하기

가장 **간단한 비동기 방식**

구조

```
API 요청
  ↓
메인 로직 처리
  ↓
별도 스레드 실행
```

예

```
주문 생성
↓
이메일 발송 스레드 실행
```

장점

- 구현 쉬움
- 빠르게 적용 가능

단점

- **서버 장애 시 작업 유실**
- **재처리 어려움**
- **확장성 낮음**

→ **가벼운 작업에만 적합**

---

# 2. 메시징 시스템 이용하기

메시지 큐를 이용한 **대표적인 비동기 방식**

구조

```
시스템A → 메시징시스템 → 시스템B
```

예

```
주문 서비스
   ↓
메시지 큐
   ↓
알림 서비스
포인트 서비스
통계 서비스
```

장점

- **서비스 분리**
- **장애 격리**
- **확장성 좋음**

단점

- **메시징 시스템 연동 이슈로 오발송**
- **중복 처리 가능성**
- **운영 복잡**

---

# 3. 트랜잭션 아웃박스 패턴

DB 트랜잭션과 메시지 전송 **일관성 문제 해결 패턴**

문제 상황

```
DB 저장 성공
메시지 전송 실패
```

→ 데이터 불일치 발생

해결 구조

```
1. DB 저장
2. Outbox 테이블에 이벤트 저장
3. 별도 프로세스가 메시지 전송
```

구조

```
Service
  ↓
DB 저장 + Outbox 기록 (같은 트랜잭션)
  ↓
Outbox Processor
  ↓
메시지 큐 전송
```


- **데이터 일관성 보장**
- **메시지 유실 방지**


---

# 4. 배치로 연동하기

일정 주기로 **모아서 처리**

구조

```
데이터 저장
↓
배치 실행
↓
외부 시스템 전송
```

예

```
하루 매출 집계
정산 데이터 전달
통계 계산
```

장점

- 시스템 단순
- 안정성 높음

단점

- **실시간 처리 불가**

---

# 5. CDC(Change Data Capture) 이용하기

DB 변경 데이터를 **자동으로 이벤트로 전달**

구조

```
DB 변경
↓
CDC Tool
↓
메시지 큐
↓
다른 서비스
```

예시

```
Order 테이블 INSERT
↓
CDC 감지
↓
OrderCreated 이벤트 생성
```

장점

- **서비스 코드 수정 최소화**
- **데이터 변경 자동 전파**

단점

- **솔루션을 도입해야 하는듯?**
