# 네트워크 기본 개념 정리

## 1. 패킷(Packet)

네트워크를 통해 전송되는 **데이터의 단위**로, 크게 **헤더(Header)**와 **페이로드(Payload)**로 구성됨.

* **Header** : 패킷의 발신자와 수신자 정보 등을 포함
* **Payload** : 실제 전송할 데이터가 담기는 영역
* 데이터의 크기가 큰 경우 일정 크기의 여러 패킷으로 나누어 전송

---

## 2. DNS와 도메인

도메인 이름에 해당하는 **IP 주소는 DNS 서버를 통해 확인 가능**함.

```text
example.com → 1.2.3.4
```

Local 환경에서는 `hosts` 파일 등을 이용하여 **도메인과 IP를 직접 매핑**할 수 있으며, 하나의 도메인에 여러 IP를 매핑하는 것도 가능함.

```text
example.com → 192.168.0.10
example.com → 192.168.0.11
```

---

## 3. 공인 IP와 사설 IP

**공인 IP**는 인터넷에서 사용하는 IP 주소이며, **사설 IP**는 내부 네트워크에서 사용하는 IP 주소임.

사설 IP는 서로 다른 내부 네트워크에 존재하는 경우 **동일한 IP 주소 사용이 가능**하며, 다음 세 가지 대역으로 제한됨.

```text
10.x.x.x
172.16.x.x ~ 172.31.x.x
192.168.x.x
```

예를 들어 서로 다른 네트워크라면 동일한 사설 IP 사용이 가능함.

```text
회사 A 내부 서버 → 192.168.0.10
회사 B 내부 서버 → 192.168.0.10
```

---

## 4. NAT(Network Address Translation)

**네트워크 주소를 변환하는 기술**로, 사설 IP와 공인 IP를 변환하는 역할을 담당함.

통상적으로 라우터 또는 스위치 등의 네트워크 장비에서 처리함.

* **SNAT(Source NAT)** : 내부 → 외부 통신 시 사설 IP를 공인 IP로 변환
* **DNAT(Destination NAT)** : 외부 → 내부 통신 시 공인 IP를 사설 IP로 변환

```text
SNAT

사설 IP
   ↓
  NAT
   ↓
공인 IP


DNAT

공인 IP
   ↓
  NAT
   ↓
사설 IP
```

---

## 5. VPN(Virtual Private Network)

인터넷과 같은 **공용 네트워크에서 서로 다른 네트워크 간 암호화된 연결을 제공**함.

서로 떨어진 두 네트워크를 연결하여 마치 **하나의 사설 네트워크에 존재하는 것처럼 통신 가능**함.

```text
[내부 네트워크 A]
        │
    암호화된 VPN
        │
[내부 네트워크 B]
```

## 6. TCP와 UDP

### TCP(Transmission Control Protocol)

**연결 기반 프로토콜**로, 노드 간 연결을 먼저 수립한 후 데이터를 송수신함.

3-Way Handshake를 통해 연결을 수립하며, 패킷의 순서와 정상 수신 여부를 확인하고 유실된 패킷을 재전송하여 **안정적인 데이터 전송을 제공**함.

```text
Client                Server

  │ ----- SYN ------> │
  │ <--- SYN + ACK -- │
  │ ----- ACK ------> │

       연결 수립
```

전송 신뢰성을 보장하기 위해 **Sequence Number, ACK, 재전송, 패킷 순서 관리** 등의 기능을 사용함.

다만 이러한 처리 과정이 추가되므로 UDP보다 상대적으로 느리며, 패킷 유실 시 해당 패킷이 다시 도착할 때까지 이후 데이터 처리가 영향을 받는 **HOL(Head Of Line) Blocking**이 발생할 수 있음.

```text
패킷 1 → 정상
패킷 2 → 유실
패킷 3 → 도착
패킷 4 → 도착
          ↓
    패킷 2 재전송 대기
          ↓
    패킷 2 도착 후 처리
```

### UDP(User Datagram Protocol)

TCP와 달리 **별도의 연결 과정 없이 데이터를 바로 전송**함.

데이터가 정상적으로 전달되었는지 확인하거나 유실된 데이터를 재전송하는 과정이 없기 때문에 구조가 단순하며 TCP보다 상대적으로 빠름.

```text
Client                Server

  │ ---- Data ------> │
  │ ---- Data ------> │
  │ ---- Data ------> │
```

### TCP / UDP 비교

| 구분     | TCP             | UDP      |
| ------ | --------------- | -------- |
| 연결 방식  | 연결 기반           | 비연결      |
| 연결 과정  | 3-Way Handshake | 없음       |
| 데이터 순서 | 보장              | 보장하지 않음  |
| 패킷 유실  | 재전송             | 별도 확인 없음 |
| 신뢰성    | 높음              | 상대적으로 낮음 |
| 속도     | 상대적으로 느림        | 상대적으로 빠름 |

## 7. QUIC

**UDP를 기반으로 TCP의 연결 관리 및 신뢰성 관련 기능을 QUIC 프로토콜 수준에서 제공**함.

UDP 자체는 패킷 순서, 전달 여부, 재전송 등을 보장하지 않지만 QUIC에서 해당 기능을 직접 처리함.

주요 기능은 다음과 같음.

* 연결 관리
* 패킷 손실 확인 및 재전송
* 데이터 순서 관리
* 암호화 통신
* 다중 스트림(Stream) 처리

구조적으로 TCP 대신 **UDP 위에서 QUIC가 연결 및 전송을 관리하는 형태**임.

```text
기존 TCP

Application
    │
   TCP
    │
   IP


QUIC

Application
    │
  QUIC
    │
   UDP
    │
   IP
```

### QUIC와 HOL Blocking

TCP에서는 하나의 연결을 통해 데이터를 처리하기 때문에 패킷 유실이 발생하면 해당 패킷이 재전송될 때까지 이후 데이터 처리에도 영향을 줄 수 있음.

QUIC는 하나의 연결 내부에서 데이터를 **여러 개의 독립적인 Stream으로 구분하여 처리**함.

```text
QUIC Connection

├─ Stream 1 → 패킷 유실 / 재전송
├─ Stream 2 → 정상 처리
└─ Stream 3 → 정상 처리
```

특정 Stream에서 패킷 유실이 발생하더라도 다른 Stream의 데이터 처리를 계속할 수 있어 **TCP에서 발생하는 HOL Blocking의 영향을 줄일 수 있음**.

### TCP / UDP / QUIC 비교

| 구분           | TCP      | UDP      | QUIC             |
| ------------ | -------- | -------- | ---------------- |
| 기반           | TCP      | UDP      | UDP              |
| 연결 관리        | 지원       | 없음       | QUIC에서 지원        |
| 패킷 순서 관리     | 지원       | 없음       | 지원               |
| 패킷 재전송       | 지원       | 없음       | 지원               |
| 신뢰성          | 높음       | 상대적으로 낮음 | 높음               |
| 속도           | 상대적으로 느림 | 빠름       | 빠른 연결을 지향        |
| HOL Blocking | 발생 가능    | 해당 없음    | Stream 단위로 영향 감소 |

결과적으로 각 프로토콜의 특징을 간략하게 정리하면 다음과 같음.

```text
TCP
→ 연결 + 신뢰성

UDP
→ 단순한 구조 + 빠른 전송

QUIC
→ UDP 기반
  + 연결 관리
  + 신뢰성
  + 다중 Stream
  + 암호화
```

**QUIC는 UDP의 단순하고 빠른 전송 방식을 기반으로 하면서, TCP에서 제공하던 연결 관리와 신뢰성 관련 기능을 QUIC 프로토콜 수준에서 구현한 프로토콜로 정리할 수 있음.**
